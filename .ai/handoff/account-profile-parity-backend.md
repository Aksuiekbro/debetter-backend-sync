Implementer: backend_implementation, different from issue author backend_audit. Scope: backend issues #17, #18, #19. Branch: codex/account-profile-parity. No commit, push, issue closure, production writes, or deployment.

Implemented account PATCH normalization/validation, real nickname mapping, conflict preflight plus database uniqueness, row-locked atomic edits/password handling, self-only session snapshot refresh with preserved trust/authorities, and transactional old-username token revocation. The caller's cookie is cleared after self rename; the current HTTP session remains usable. Passwords are never trimmed; null means omitted, including for whitespace-only supplied passwords. Newly registered accounts receive an empty authority collection so their first authenticated edit works.

Implemented safe identical401 invalid-login JSON and deliberate400 absent-credential handling; successful session credentials are null. Registration auto-login remains supported. JSON rememberMe opt-in is passed as a private server attribute, the provider key matches the persistent service, and false/omitted/query-only opt-in cannot create a cookie. Logout is matched against the configured servlet path with the existing200 response, validated cookie-only logout revokes tokens, and expired cookies are rejected/canceled without revoking other devices' live tokens. Expired rows are left to the existing token lifecycle; explicit logout, rename, and theft detection retain account-wide revocation.

Schema addition: db/changelog/create_persistent_logins.sql, included from master changelog, creates the standard JDBC token table and username index idempotently. Existing compatible token rows survive reapplication. This is necessary because there was no tracked table migration. Production migration has not run.
